# Mizan: mobile, accessibility and performance review (round 1)

**Score: 73/100.** The accessibility basics are careful and mostly correct. It loses points on contrast where hero text sits over the 3D scene, on control borders that are too faint, on filter results that screen readers never hear, and on a phone experience that is long and hides content.

## What works

- **Real still-page fallback.** `prefers-reduced-motion` and missing WebGL both switch to `.mode-static` (`App.tsx:21`). The page then drops the scroll tracks, shows all five parts as an `<ol>`, and replaces scroll-driven time with a labelled `<input type=range>` that has `aria-valuetext` (`TimeSection.tsx:477`). The setting is watched live (`useReducedMotion.ts`), and the CSS turns off transitions and smooth scrolling.
- **Keyboard and dialog basics are right.** There is a skip link, and a global 2px ink `:focus-visible` ring (inverted on the footer) that measured visible on every one of 32 tab stops at 360px. Tab order follows the visual order. Focused controls are never hidden under the sticky nav, because `scroll-padding-top` is set. The record dialog moves focus in, traps Tab (Close, 3 rule buttons, JSON toggle, then back to Close), closes on Esc, locks page scroll, and returns focus to the button that opened it. All of this was tested.
- **Semantics.** Headings run h1, then h2 §1–§5, then h3, with no skipped levels on the page. The register table has a `<caption>`, `th scope=col/row`, and a real `<button>` in each row header. Toggle groups use `role=group` and `aria-pressed`. Matrix ticks carry sr-only "accepted / not accepted". Status is shown by icon plus word plus colour, never colour alone. Arabic text has `lang="ar"` (and `dir="rtl"` in the footer).
- **Text colour tokens all pass AA.** Measured: ink-3 #56626B is 5.29:1 on paper and 4.78:1 on paper-2. Status tags range from 5.20 to 6.53:1, and brass-ink is 5.47:1. axe-core found 0 violations on desktop and mobile.
- **Phone layout holds.** There is no horizontal overflow at 360 or 390 (`scrollWidth` equals the viewport). Below 640px the table becomes full-width card buttons. Nearly every control is at least 44px tall.
- **The 3D is careful with cost.** three.js (128 KB gzip) loads lazily on `requestIdleCallback` after the content renders. It draws only when something changes, and stops when the modal is open or the page is past `#who`. Device pixel ratio is capped at 1.5 on small screens, with 512px shadow maps. CLS is 0.0004.

## Top 5 recommendations (ranked by score impact)

1. **Give the hero copy a backing that can't fail.** Keep the gradient fully opaque (0.92 or more) to the right edge of the text column plus 40px: for example `linear-gradient(90deg, var(--paper) 0, rgba(243,235,221,.94) 52%, rgba(243,235,221,0) 72%)`. Or put `.lede` and `.audiences` on a `background: rgba(243,235,221,.9)` panel. Rerun the pixel sample at 1024, 1280 and 1440, with a target of 0% below 4.5:1.
2. **Stop hiding content on phones and fix the pinned panels.** Below 760px, render §1 and §2 as the static versions (the numbered list and the range slider) even when 3D is on. The scene can still move behind them while the user scrolls normally. This brings back the ledes, the roles list and the date controls, and removes about 3.6 screens of track. Separately, for landscape phones, add `@media (max-height:500px)` with `.sticky{position:static}`, or `max-height: calc(100svh - var(--nav-h) - 24px); overflow:auto`.
3. **Make the register controls and results accessible.** Darken control borders to at least 3:1. `#8C7E66` is about 3.6:1 on sheet; use it for `.search`, `select`, `.seg` and `.jumps`. Wrap "Showing N of 8 records" and the empty state in `<p role="status">`. Move `aria-live` from the whole hero card to a small sr-only `role=status` line such as "Sample Token A: Active, Approved".
4. **Add section navigation below 1080px.** A "Sections" `<button aria-expanded>` that opens the five links as a list (or a horizontally scrolling chip row under the header) is enough. Also show a short "Demo" flag at ≤420px instead of hiding it.
5. **Tidy the dialog and the 3D steps for screen readers.** Make the dialog title an `h2` and its section headings `h3`. Set `inert` on `main`, `header` and `footer` while it is open. Put the rule descriptions in visible text under the buttons instead of `title`. Make the rule buttons a full-width column on small screens. In 3D mode, add an sr-only `<ol>` with all five parts (or make `.step-body` `aria-live="polite"`). Add a `webglcontextlost` handler that calls `onFail`.

## What would get this to 85+

Hero text should never depend on what the 3D scene happens to draw behind it. Phones should get the same content as desktop, in a page under about 9 screens at 390px, and short landscape screens should never clip a pinned panel. Control borders need at least 3:1, filter results need to be announced, and smaller screens need a way to reach every section. With those fixed, plus prerendered HTML so the hero paints before React loads, this would be clean, well-built WCAG 2.2 AA work.
