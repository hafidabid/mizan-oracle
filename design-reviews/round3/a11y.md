# Mizan: mobile, accessibility and performance review (round 3)

**Score: 80/100** (round 2: 79). Accessibility is now essentially clean. The pinned panels, the dialog, the header offsets and the phone page length are all better, and the measurements confirm it. The score barely moves for three reasons. The new framed-arch hero pushes the headline below the fold on tablets in portrait. The desktop page grew by 2 screens. Layout shift crept up on phones.

## What works

- **The pinned panels fit now.** At 800×690, 1024×690, 1024×768, 1100×690, 1280×700, 1366×768 and 1440×900, I scrolled through all five §2 steps and the §3 track. The panel was never cut off below the screen and never sat under the header (the bottom was at most 586px on a 690px screen). The still page now applies at `max-height: 680px` (`App.tsx:28`), which covers the 560–600px cases that failed in round 2.
- **The header's height is measured.** `--nav-h` comes from a `ResizeObserver` on the header (`Nav.tsx`), so scroll padding and sticky offsets match the real header. In slow tab runs (48 stops at 390×844 and 1024×768), focus never landed under the header or off-screen. At `max-height:500px` the header stops being fixed (`.nav{position:absolute}`), so landscape phones no longer lose 25% of the screen. The link row has a fade at its right edge and scrolls the current link into view. The current-section underline is now lapis (9.85:1, up from 2.69:1).
- **The phone page is shorter.** 9,906px is 11.7 screens at 390×844 (round 2: 12.8). It is 13.2 at 360 (14.7) and 17.5 at 320 (19.7). The type filter collapses into a `select` on phones. In §5, Fields and Verify are `<details>` closed by default on phones. The board's reasoning in the dialog starts folded on phones. The dialog is 1771px at 360 (round 2: 2382), and its rule buttons are a clean full-width column (3 × 258×44px).
- **The dialog is correct.** Focus goes to the `h2` title. Tab moves to "The board's reasoning", Shift+Tab goes to Close, and the cycle wraps properly (`RecordModal.tsx`: `if (i === -1) return`). The background is `inert`, and Esc restores both the hash and the focus. The fake PDF link is now plain text: "MZN-001.pdf (demo, not hosted)".
- **Contrast and semantics hold.** I sampled the pixels behind the hero text over the 3D scene at 1024, 1280, 1440 and 1920. Everything sits on solid paper, with a minimum of 8.26:1 for the intro paragraph and 0% of pixels below 4.5:1. In 3D mode, screen readers get all five steps as a single sr-only `<ol>`, and the visible card is `aria-hidden`. That fixes round 2's problem of invisible text that find-in-page could still match. axe-core (WCAG 2.2 AA plus best practice) found 0 violations at 390, 800 and 1440 on the page, and with the dialog open.
- **Phones still never download three.js.** The mobile network log shows only `index.js` (90 KB gzip) and CSS.

## Top 5 recommendations (ranked by score impact)

1. **Fix the tablet hero.** For widths up to 900px: either put the frame after the copy (`.mode-3d .hero-art{order:0}`), or cap it at about `min(32vh, 280px)` so the h1 and the sample record both appear on the first screen at 768×1024 and 800×700. Or send widths up to 900px to the still page as well, which also spares tablets the three.js download. Check that the h1 top is under 60% of the screen height and the "Open record" button is visible at 768×1024.
2. **Remove the header layout shift.** Set the default `--nav-h` in CSS to the real values: `@media (max-width:1080px){:root{--nav-h:98px}}` and `@media (max-width:340px){:root{--nav-h:138px}}`. Then the ResizeObserver only fine-tunes it. Self-host and preload Plex Sans 400 and Serif 500 with `size-adjust` fallback faces. Target CLS under 0.01 and mobile LCP under 2.5s.
3. **Shorten the scroll tracks back to about 170vh/140vh.** Or make each step about 35vh, so §2 is at most 2 screens and the desktop page is about 9.5 screens again. Five short cards don't need 2340px.
4. **Trim the phone page further.** On ≤640px, drop the code field from each §2 step (or put all five fields behind one `<details>`), show §4's seats as a compact definition list, and merge "Next steps" into the footer. Aim for 9 screens at 390.
5. **Smaller polish.** Fix the §2 card's height to the tallest step (`min-height` measured once) so it stops jumping. Add the field values to the sr-only list. Move the header button into the link row at 340px or less so the header stays at one height.

## What would get this to 85+

The accessibility work (focus, dialog, semantics, contrast, announcements) is now at a level where I would not block on anything. To reach 85+, every screen size needs to put content first. Tablets in portrait should see the headline and the sample record without scrolling. Desktop should go back to about 9 screens. Phones should reach 9 screens with no layout shift from the header or fonts. Prerendered HTML so the hero paints before the 90 KB bundle runs would put it clearly into the excellent range.
